Modec back to ToC or Class ToC

IRI: http://example.org/muac_onto/Mode

An abstract label applied to a user selectable option that enables a set of use case-based system capabilities to be employed in conjunction with organizational processes and procedures to command and control (C2) a system, product, or service to achieve a specified set of mission objectives, outcomes, and levels of performance. Triggering events serve as entry and exit criteria for transitioning into and out of a mode. Modes can have sub-modes.
Example
When a system is in a failed state, the supervisor can make the decision to switch mode of operation from primary to fallback operations. This mode change causes the state of the fallback system to be Operational

Phasec back to ToC or Class ToC

IRI: http://example.org/muac_onto/Phase

A designation applied to segments of the System / Product Life Cycle or Mission Lifecycle of a system, product – e.g., Pre-Mission, Mission, or Post-Mission. Phases may consist of sub-phases – e.g., an aircraft’s Mission Phase of operations may be partitioned into Phases of Flight (subphases) such as take-off, ascent, cruise, or land.

A flight consists of seven primary phases: preflight, taxi, takeoff, climb, cruise, descent and approach, and landing/roll-out

Statec back to ToC or Class ToC

IRI: http://example.org/muac_onto/State

An attribute used to characterize the current logistical employment, status, or performance-base condition of a system, product, or service or system components at the element, subsystem, assembly, subassembly, etc. levels of abstraction. Based on principles of physics, “states” are observable, measurable, verifiable.
editorial note
The state vs phase confusion is large e.g ICAO defines INCERFA, ALERFA as phases. This contradicts definitions of Wasson as these designations represent condition-based safety or readiness conditions rather than planned, time-based segments of a mission, placing them under the definition of system states.
Example
A system element is nominal state when it performs its intended functions. Physical failures or changes in its environment can cause it not to perform intended functions or even performed unintended functions then this system element is in a failed state.
has super-classes
behavioral interval c
is in range of
has state op
